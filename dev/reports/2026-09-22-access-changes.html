01What changed, in short

  1. Team default now grants the same model groups as dream. It is the team every OAuth/SSO key lands in, so it was silently capping every CLI and agent client at 72 models with no Claude and no Bedrock.
  2. The test-do-not-use team was deleted. Its own comment documented that its mcpServers grant defeated the mcpToolsets restriction it existed to demonstrate.
  3. alitellm-auth v0.15.0 can request and surface the user's identity-provider groups. Enabled in this deployment; 21 real Workspace groups now arrive on every login. Nothing consumes them for authorization yet — this is the groundwork for granting access from groups instead of from a single team.

MCP access was not changed. It was already close to uniform and matches the intent that most people should reach roughly the same servers.

Why default is special context

alitellm-auth mints a dedicated per-user key (metadata.key_alias = "front") the first time an OAuth token is resolved, and it always places it in LITELLM_DEFAULT_TEAM — which is default. Nothing asks the user, and the key is never shown to the browser. So the grants on default are the SSO capability set for everyone: opencode, Claude Code and Codex via ackstorm-token, and the device grant. This is now written into the file so the next person does not re-learn it the hard way.

05SSO groups wiring

Dex was already configured to resolve Google Workspace groups — service account mounted at /etc/dex/sa, domainToAdminEmail set for ackstorm.com — but no client had ever asked for the groups scope, and nothing in alitellm-auth read the claim.

New setting

env
OAUTH_SCOPES
helm
config.oauthScopes
app default
"openid email profile" — groups OFF
this deployment
"openid email profile groups"

It governs both sign-in legs, which previously hard-coded separate strings: the console login (configure_auth) and the authorization-server leg (_dex_scope(), which appends offline_access).

Why it ships disabled by default failure mode

The Directory API lookup requires domain-wide delegation for admin.directory.group.readonly. Without it Dex fails the login rather than omitting the claim — and this is the only sign-in path there is, for the console and for every OAuth client. A default-on setting would mean a fresh deployment without that delegation loses all authentication.

So it is opt-in per deployment, and rolling back is clearing one Helm value and restarting. No image rebuild, no release.

What arrives now

GET /api/session/me gained a groups array. For the signed-in account it returns 21 groups:

everyone@architect-team@managers@team_leaders@direccion@projects@blueprints@aws@administracion@billing_gcp@legal@abuso@ackstorm_governance@official_communications_google@oferta_ganada@project-closed@sendgrid@tech_support_editor_gcp@zoho_admin@zoho_projects_admin@cttexpress-ficodes@

All @ackstorm.com. Claim normalisation (normalize_groups) accepts a list, a bare string, or nothing, and degrades to [] rather than raising — a provider that stops sending groups must never break a login.

Nothing consumes them yet by design

Groups are stamped on the session and logged at both callbacks. No authorization decision reads them. This is deliberately one reversible step: prove the claim arrives and that logins stay healthy, before anything depends on it.
